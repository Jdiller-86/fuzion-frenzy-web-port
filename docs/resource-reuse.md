# SDK-first M1 execution

The active implementation route is the existing matching Fuzion SDK. Build-run-fix toward the first original browser frame, then a controllable original menu or selected minigame. Before the working baseline, compile and run the actual affected path, inspect its output/failure and use only quick diagnostic checks. Batch shared-interface fixes and reuse passing evidence. Detailed testing, broad matrices and repeated per-caller/historical audits come later. Native output, fixtures and compilation alone are not original browser execution.

## Bounded desktop reference, then browser attempt

A native desktop reference is useful for a short diagnostic pass: verify and reuse a matching retained executable, or build it locally from the pinned source and the same private game input. It can expose a simple host-side baseline and clarify a visible frame or input behavior. It is not a product path, an M1 acceptance result, or a source of a convertible executable. Its kernel, VM, threads, files and renderer are native implementations; the browser attempt must compile the same C++ source and bridge those contracts explicitly.

Limit native-reference setup/build/run to the first **30 minutes** of the initial work session; give a short progress update at **150 minutes** and continue productive work. Then attempt the browser build/run with that same source, configuration and local game input. The 30 minutes are a diagnostic allocation, not a deadline to finish the native port. If the retained executable is absent or the build is blocked, record the exact command, elapsed time and failure, then continue independent browser compilation and interface work. Do not wait for a complete native product.

At 150 minutes give a brief progress update and continue productive implementation. Keep actual commands, identities, observed output/failure and the next concrete fix in a compact local record; expand formal evidence and timing analysis after the baseline. A first frame or failure report does not close #49 or accept M1. Fix supported build/runtime failures and keep working toward the original baseline. Pause only affected execution for missing private inputs, an unresolvable external dependency, unsafe resource/content behavior or missing source authority; continue useful independent work. The 150-minute checkpoint is not a stop while productive work remains.
