# OpenCode model routing and development workflow

The continuous target and local five-minute scheduled cycle are in [the OpenCode goal](OPENCODE_GOAL.md).

This repository uses [the project OpenCode V2 configuration](../.opencode/opencode.jsonc). It leaves the working global OpenCode Go, OpenAI OAuth, Unsloth and REA connections intact. OpenCode 2.2.5 discovers the project config when started in this repository. A fresh session defaults to `builder` with `opencode-go/deepseek-v4.1-flash`; existing sessions retain their own selected agent and model until changed explicitly.

| Agent | Provider/model | Use | Tool boundary |
| --- | --- | --- | --- |
| `builder` | `opencode-go/deepseek-v4.1-flash` | Bounded implementation, tests, task coordination | May edit source and delegate to `scout`, `reviewer` or `architect`; no REA |
| `scout` | `unsloth/qwen3.8-27b` | Narrow local source search, classification, REA evidence | Read-only; no shell, edit or further delegation; only selected REA inspection tools |
| `reviewer` | `opencode-go/glm-5.3` | Independent correctness review of high-risk changes or unresolved bugs | Read-only; no shell, REA or further delegation |
| `architect` | `openai/gpt-6.1-sol` | Architecture, milestone design, difficult decisions and final evidence review | Primary or bounded subagent, read-only; a primary session may delegate work to cheaper agents |

Project policy allows only `builder`, `scout`, `reviewer` and `architect` child agents. The builder may call Sol without a separate user approval when the escalation rules below apply; a subagent cannot delegate again at the default depth limit. Its OpenAI provider is the active linked ChatGPT/Codex OAuth method (`chatgpt-token-sharing`), not an API key. To start with Sol as the primary architect, select both `architect` and `openai/gpt-6.1-sol` in a new Desktop session. Selecting a primary agent alone does **not** switch an existing session's model. On the CLI, use `opencode run --agent architect --model openai/gpt-6.1-sol "<architecture question>"`. The default CLI run uses DeepSeek Go. Never substitute `opencode/deepseek-v4.1-flash` or `opencode/gpt-6.1-sol`: those are different provider routes.

## One bounded task

1. Read `AGENTS.md`, the current handoff/status, the relevant checkpoint and the affected source. Capture a task card with a concrete result, files in scope, acceptance checks, evidence boundary and unresolved questions.
2. Delegate a narrow search or local REA question to `scout` when it fits its 8,192-token context. Ask for paths, evidence IDs and uncertainty, not a dump of proprietary bytes. Direct Ghidra remains the XBE route documented in `ANALYSIS_SETUP.md`; REA's Windows XBE admission is not assumed.
3. Use `builder` for the smallest coherent implementation. For CPU instruction semantics, memory accounting, ABI, GPU compatibility or an unresolved correctness defect, obtain an independent `reviewer` finding against actual changed code and tests. A review is evidence to inspect, not a substitute for executing the original title.
4. Escalate automatically to `architect` when a decision changes the project route or multiple subsystems, two targeted attempts fail, or a GLM review leaves a material CPU, memory, ABI or GPU correctness question unresolved. Send: objective; observed behavior; exact evidence/checks; attempts; remaining hypotheses; decision needed. Use one bounded Sol call per decision; return implementation to DeepSeek. Stop and report if that call cannot resolve the decision.
5. Finish with changed files, checks actually run, observed original-runtime behavior, remaining gaps and next task. Update `PROJECT_STATUS.md`; record consequential choices in `DECISIONS.md`. Do not claim a playable game from translated-function counts or component fixtures.

Agent step caps (builder 48, scout 8, reviewer 12, architect 8) stop a single prompt sequence; a new user input resets the cap. They are usage brakes, not billing limits. The project policy blocks environment-file reads/edits, external-directory tool access and direct Git push/merge commands. Shell commands and plugin code are **not** contained by these project rules, so do cloud-model work in a clean source-only worktree and inspect tool prompts. Do not put original game files, converted assets, pseudocode, credentials or raw research logs in prompts, issues, PRs or model attachments. Local Qwen can analyze local evidence; send cloud models only curated findings.

OpenCode Go's **Extra Usage** setting can fall back to pay-as-you-go balance after the included limit. The Personal workspace currently shows Extra Usage **Off**. The primary runner changes only its own per-run `--model` after a recognized allowance or model-availability failure: `opencode-go/deepseek-v4.1-flash` → `opencode/deepseek-v4.1-flash-free` → `opencode/glm-5.3-flash-free`. After a Go allowance failure it tries the free route for one hour before probing Go again. The geometry runner always selects `opencode/deepseek-v4.1-flash-free` and waits for the next hourly tick if it is unavailable; it never falls back to a different model. Each lane records its selected model in ignored cycle state. Other errors keep the task in retry state instead of triggering another model. Both free routes answered a live minimal request on November 3; their availability can change. OpenCode [lists DeepSeek V4.1 Flash Free and GLM-5.3-Flash Free as temporary free models with zero-retention and no-training provider policies](https://opencode.ai/v2/docs/console/models/). Use only curated source-owned context on any cloud route; original game inputs remain local. This fallback does not spend Console balance or change global OpenCode/Codex settings.

If Sol's linked-account allowance is exhausted, keep consequential architecture decisions open and work on independent bounded tasks. A free second opinion can be requested explicitly with `opencode run --agent architect --model opencode/glm-5.3-flash-free "<concise source-only decision report>"`; label it a free-model review, not a Sol decision. For a Go GLM review limit, use `opencode run --agent reviewer --model opencode/glm-5.3-flash-free "<narrow source-only review>"`. These commands use separate sessions and do not overwrite the pinned builder's model. Local Qwen remains an optional source-only scout after its OpenCode handoff is repaired. Do not represent a free fallback as equivalent to an unavailable higher-reasoning review.

## Source control and GitHub

Use a clean worktree from a reviewed source-only commit for cloud agents. The main checkout contains ignored `research/` and player-supplied game files, so a Git ignore rule alone is not an isolation boundary. The local `.worktrees/` directory is ignored. Keep one branch/task owner per worktree; use `codex/<task>` names. Do not copy ignored material into a worktree or access the main checkout's ignored game/research inputs from a cloud-agent shell. Follow the current handoff for the active runtime boundary.

Two scheduled lanes may work concurrently with separate OpenCode Desktop sessions and Git branches. The five-minute `opencode-source` lane owns original startup, runtime services, device/memory/FATX work, route decisions and the broad project status. The hourly `opencode-geometry` lane owns only source-owned `src/runtime/nv2a_*` components, their matching tests and `docs/NV2A_GEOMETRY_CHECKPOINT.md`. It works on an independent branch based on the last committed source-lane checkpoint; it must not modify the primary lane's files, claim original rendering from a fixture, or use ignored game/research inputs. Each lane has its own lock, state and session pin; at most one builder prompt per lane runs at once. The geometry lane uses only `opencode/deepseek-v4.1-flash-free`; it does not call Go, Sol or other-model subagents. A material correctness blocker is recorded for the primary lane. Review and integrate geometry changes into the original-execution lane separately when a concrete dependency is reached; do not automatically merge branches.

The hourly `FuzionFrenzy-OpenCode-Architect` audit reads a separate clean `opencode-architect` snapshot fast-forwarded to committed `codex/opencode-source`. It uses linked-account `openai/gpt-6.1-sol` as the primary read-only architect, with one bounded review per hour and no implementation or delegation. Its ignored guidance record names the reviewed commit, model and concise priorities. The primary builder receives guidance less than two hours old as untrusted context, verifies it against the live worktree and skips completed or unsupported advice. Sol allowance or model unavailability permits a labeled provisional review on `opencode/glm-5.3-flash-free`; a free review does not settle a consequential route decision. The architect cannot edit or merge either builder branch. This adds strategic checks without duplicating implementation or sending original game files to cloud models.

Use a GitHub issue with a task card when useful, then a scoped branch/worktree, targeted tests, a source-only pull request and human review before merge. The public GitHub repository and source-only CI already exist. OpenCode does not yet have a verified GitHub issue/PR connector, and `gh` is not installed; the existing `git` remote is sufficient for local branch work. Do not assume GitHub Actions can access localhost Unsloth, desktop OAuth or REA. Before staging, run `npm run check`, inspect the staged paths and `git diff --cached --stat`, and keep all original content and credentials out of Git history. The Windows cycle runner publishes verified commits to each lane's `origin/codex/opencode-*` branch after each successful cycle; it checks the exact branch name, changed history paths, `npm run check` and committed whitespace first. Publication failures are recorded in that lane's cycle state and retried after a later successful cycle. OpenCode itself cannot push, and merging into `main` remains a separate reviewed action.

## Quick CLI checks

Run from the repository or its clean worktree:

```powershell
opencode debug config
opencode debug agents
opencode models
opencode auth list
opencode mcp list
```

`debug config` should include `.opencode/opencode.jsonc`. `debug agents` should show the four configured roles and their exact provider IDs. `auth list` shows credential presence only; it does not prove a live model request. `mcp list` should report `rea` connected. A live smoke test is separate from these configuration checks and consumes the selected provider's allowance.
