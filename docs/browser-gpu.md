# Browser GPU candidate

The original title executes in WebAssembly and renders through WebGL2. This is a local prototype with measured improvements, not acceptance of M1, complete rendering fidelity, or locked 60 FPS on modest hardware. The native build and original inputs remain unchanged.

## Run and rebuild

Run `python tools/serve-sdk-browser.py --open --port 8765`, select a compatible local ISO and Start game. GPU rendering is the default; the slower software diagnostic is under Compatibility options. The game fills the window while preserving its original aspect ratio. F1 opens host controls; it does not pause the guest.

From the retained `.worktrees/browser-gpu` layout in WSL:

```sh
source ../../.tools/emulation/emsdk/emsdk_env.sh
python3 tools/build-sdk-browser-full.py \
  --sdk ../../.tools/candidates/xboxxbe-codegen-58757ab \
  --config ../../.tools/candidates/fuzionfrenzy-recomp-071dbd9/config/game.toml \
  --generated ../../research/verification/sdk-title-bulk-command-20261107/generated \
  --output .tools/artifacts/sdk-browser-thinlto --jobs 6 --link-opt=-O3 --lto thin
# Stop the game before installing a matched JS/Wasm/worker set.
for name in fuzion-sdk-full.mjs fuzion-sdk-full.wasm fuzion-sdk-full.worker.js full-build-manifest.json; do
  cp ".tools/artifacts/sdk-browser-thinlto/$name" ".tools/artifacts/sdk-browser-full/$name"
done
python3 tools/package-sdk-browser.py
```

The pinned SDK is `58757ab255c0a6b3929f405d7a5f1567fcd7fda3`; config checkout `071dbd97bdc098c4647cc24c99f9eae693fde1eb`, `game.toml` SHA-256 `c45bed067026b71ff2415d2b901f5bece66ad54dd94796405ce2cd0c2e1cec2f`. The measured build uses Emscripten 3.1.50 / LLVM18, O3 objects/link and native Wasm exceptions. `--exceptions js` preserves the slower development fallback and invalidates the object cache when selected. Build manifests record original title hashes; adapters modify disposable copies only. The published texture-cascade correction is consumed; native D3D12 descriptor-rollover changes remain untouched.

The browser builder supports `--lto thin` and `--lto full` for LLVM optimization across compilation units. `--lto off` selects the original development build defaults. A mode change invalidates compiled objects, and the manifest records the mode. ThinLTO caches its link results inside the build output directory. [Emscripten LTO documentation](https://emscripten.org/docs/optimizing/Optimizing-Code#lto)

## Implemented optimizations

- SDK programmable and fixed-function vertex shaders, transforms, lighting and pixel combiners execute on WebGL2. Native shader generators remain the semantic source; authored translators lower their generated HLSL.
- A bounded shader prepass starts compile/link requests from the current owned batch before geometry packing. Discovery tracks source, vertex layout, flat shading, texture kinds and shadow modes. At most 128 speculative programs are attempted per batch, with 2,048 discovered pairs and the existing 2,048 program cap. Pipelined draws covered by a resident shader keep using it until the specialized program's link and uniform locations are ready. The validation timer polls up to four queued programs per check. Other variants retain their original validation path. Draw order and guest timing are preserved. [Khronos WebGL guidance](https://registry.khronos.org/webgl/extensions/KHR_parallel_shader_compile/) · [Chromium uniform lookup](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/gpu/command_buffer/client/program_info_manager.cc)
- A per-context cache shares fragment shader objects with exactly identical generated GLSL, capped at 2,048 stages. Both stages are submitted before linking. Successful validation detaches the stages from the linked program. Link failures report compile diagnostics, and cached stages live until the context ends.
- A bounded table maps the five existing aligned guest windows, including the shared physical/write-combine backing. Translated fixed-width integer and floating-point accesses inline the same range check. Invalid spans retain the original error path, and empty spans can point one past an admitted window. The allocator and guest window capacities are unchanged.
- Generated x87 load and compare/pop sequences use one combined check for their float32 operands, including optional arithmetic. The fast path keeps the SDK precision rules, comparison status and popped stack slot. If any span fails admission, the original ordered operations run and retain any intermediate stack state written before the fault.
- The browser SDK dispatcher registers the objects each thread is waiting on while it parks. A final guest mutex release wakes dispatcher waiters only when a parked wait includes that mutex. Registration and release share the dispatcher lock, and wait-any and wait-all register each referenced object. The existing timeout and APC checks still run in their original order.
- Threaded resource-header capture resolves one checked guest span for the type and snapshot in the common case. A 12-byte header can still end at the guest window boundary. A long header requires a complete 20-byte span. The snapshot lives in the fenced scratch ring.
- The compiled state recorder checks for empty bindings before calling the capture function. Bound textures, palettes, streams and surfaces use the checked snapshot path.
- Pixel-resource descriptions use a single checked 20-byte mapping for the Common, Data, Format and Size fields. A short nonpixel header still uses the checked common word to reject the type.
- Native vertex streams bypass CPU float4 expansion and JS transposition when admitted. The initial admission is one stream, stride aligned to four bytes and at most 252 bytes, supported SDK formats and every attribute inside its stride. Complete source spans are checked before dense views or sparse gathers; the bridge owns copies before SDK assembly buffers can be reused. SDK list expansion preserves primitive/index order, including flat-shading rotation. Incompatible layouts use converted assembly.
- Typed inputs use the SDK's normalization, integer, FLOAT2H and packed 11:11:10 reconstruction. BGRA is corrected exactly once. Raw layout groups share VBO uploads and retain state barriers; converted vertices still have their own planes and index bases.
- The bridge interns consecutive, byte-identical raw layouts in the current command arena. The renderer reuses a validated layout when its owned pointer and stride match, and checks the advertised register mask on each draw. Different pointers retain exact layout comparison. This avoids a 64-byte layout copy and a JavaScript heap view on the reuse path.
- Consecutive threaded raw draws can reuse the previous owned shader, material, texture and target packets. The consumer clears reuse at state changes, non-draw commands and arena reset. The dirty revision, layout, stride, register mask, decode and pretransformed state must match. A draw that sets up a target cannot seed reuse. Each draw still assembles checked geometry and copies its vertices and indices into the command arena.
- Prepared raw draws also extend the preceding command's vertex and triangle lists. The bridge validates each original index before rebasing it. In-flight vertex and index storage remains immutable through acknowledgement. Contiguous raw-only batches read checked vertex data directly from owned Wasm memory. Mixed batches retain the staged layout and index checks. [WebGL 2 buffer object signatures](https://registry.khronos.org/webgl/specs/latest/2.0/#BUFFER_OBJECTS)
- For eligible raw-only batches, WebGL compares the next vertex span and packed indices with owned snapshots of the current buffer contents. An exact word comparison keeps matching prefixes and suffixes at the same offsets. One upload updates the changed span. Allocation growth and full-upload fallbacks invalidate the comparison state. Shadow storage is capped at 8 MiB for vertices and 2 MiB for indices.
- Programmable vertex banks compare all 768 source floats and four fog floats against the current immutable owned 772-float command payload before packing. Exact matches reuse that payload, removing the temporary 3 KB bank copy; SubmitDraw recognizes the same owned pointer and skips a second comparison. Changed banks still copy into owned arena storage. Fixed/pretransformed paths retain their existing constant/fog behavior. ResetCommands clears the cache before arena reuse, and queued blocks stay alive through acknowledgement. Render-target identity reuses the already validated backing offset, with a one-byte minimum span preserving the former zero-size endpoint check.
- Exact SIMD byte equality replaces scalar comparisons for large constants, metadata and encoded images. Consecutive pixel keys reuse stable shader text before hashing. Fixed constants cache every input actually read by the native transform/light builders; per-draw fog is refreshed and captured before reuse. No draws or simulation frames are dropped as a performance shortcut.
- Admitted 2D color textures retain owned RGBA8 bytes instead of float4 texels. BGRA8 uses the existing SDK decoder and one R/B swap; BC1/2/3 reuse its block decoder through a temporary float buffer, then retain only quantized bytes. This reduces persistent decoded CPU pixels and pinned bridge payloads from 16 to 4 bytes/pixel (75%); GPU storage was already RGBA8. The software reference keeps float sampling. Faces, encoding, spans and exact owner sizes are checked; unsupported texture classes retain existing refusals. JS reuses ordinary upload staging and updates same-sized allocations with `texSubImage2D`.
- Indices are packed and submitted in the same command order. A reusable binding array indexed by command row and a sequential byte offset replace two per-draw maps. Adjacent batching compares the identities of immutable state, uniform and texture packets interned by `SubmitDraw`. Changes in geometry binding, shader, packet contents or a clear/target command still end the pending draw. Per-program sampler address/border snapshots reuse owned arrays and retain Float32 rounding. Checked word/float views construct directly over the current heap after span validation. Draw state is borrowed during synchronous consumption, and an owned 40-word snapshot retains state comparisons across arena reuse, including offset-aware polygon-bias reinterpretation.
- Decoded textures use complete backing/descriptor/palette keys, exact content checks, dirty epochs and same-frame write invalidation. A last-successful map-node shortcut avoids large key construction and map search only after every descriptor field and all 256 fresh palette colors match. All three erase paths invalidate it before removal; hits still validate content and register the image owner for the current batch. It retains no additional image owner. Queued images retain immutable host owners. GPU targets have descriptor-only sampled views, stable color allocations and bounded FBO/layout caches. Lossless readback coherence avoids redundant uploads; lossy formats keep conservative handling.
- The browser dirty table publishes its revision after committing a mark under the mutex. A thread can reuse one of 32 recent dirty epochs only when both the full data address and the acquired revision match. A miss reads the map and revision under the mutex.
- Each of four texture stages retains a borrowed successful map node for image-version and pinned-copy metadata within the command batch. Hits require the exact pointer key and current generation; version fields are read from the current node after registration updates. Misses are not cached, and ResetCommands invalidates every slot before either map is cleared. Existing size/encoding checks, pinning and conservative fallback remain. No additional image owners are retained.
- Threaded preparation and one-flight pipelining overlap C++ work and JS submission. Scratch reservations, resource barriers, queue/payload caps and acknowledgement before reuse protect ownership. Current plus in-flight command arenas stay bounded. Failure remains an explicit stop.

Raw streams, GPU vertices, threading and pipelining default on. Development fallbacks: `?rawVertices=0`, `?cpuVertices=1`, `?threadedGpu=0&pipelinedGpu=0`, or `?pipelinedGpu=0`. `?shaderPrewarm=0` disables the optional shader prepass. Restart after changing switches. Software rendering remains serial. The optional `?gpuTiming=1` enables local asynchronous GPU elapsed sampling; it defaults off and requires a restart.

The pipelined renderer validates WebGL commands after submission. Each new frame replaces the pending fence and preserves the first check's 250 ms deadline. The timer uses zero-timeout polls and reads errors after the latest fence signals or the deadline expires. Explicit guest flushes and readbacks still validate before returning or copying pixels. Stop and context loss cancel the fence and timer. Use `?gpuErrorChecks=sync` for synchronous validation inside each frame batch. [WebGL 2.0 specification](https://registry.khronos.org/webgl/specs/latest/2.0/) · [Chromium error-query implementation](https://chromium.googlesource.com/chromium/src/+/refs/heads/main/gpu/command_buffer/client/gles2_implementation.cc#739)

## Timing and presentation polish

Windows uses browser-timer pacing by default. `?precisePacing=1` enables it explicitly and `?precisePacing=0` restores coarse waits. A non-main PThread sleeps on a private futex while the runtime JS agent schedules the absolute deadline. The callback rounds positive timer delays up and refreshes its shared-memory view before it signals. The Windows frame cap can schedule a wake up to 2 ms before its deadline on waits longer than 2 ms. The game thread polls the final interval when its clock confirms that bound. `?frameCapPrecision=0` uses whole-millisecond frame-cap timers while retaining browser-timer pacing. Virtual blank and event hold use the ordinary deadline timer and the original guest event sequence. Cancellation stays disabled until the callback releases the signal storage.

An actual runtime-worker probe requested 16.667 ms `Atomics.wait` sleeps and measured a 31.18 ms median here. Browser `setTimeout` was better but still late at times. In five menu windows, the SDK virtual-blank rate improved from about 42-43 Hz to 57-59 Hz; this is an independent SDK counter, not a physical-display measurement. The timer remains best-effort under load and background throttling.

`prepareCompletionIntervalMs` measures intervals between render-consumer EndFrame timestamps after Present returns; in pipelined mode, Present queues the current frame and may wait for the prior flight. It does not timestamp completion of the current GPU work. `metricsCallbackIntervalMs` measures diagnostics delivery, with `frameMs` retained as its alias. Neither proves physical display cadence. The gpu-frame message follows submission and gl.flush(), not GPU completion or display. FPS counts completed metrics callbacks, and JS submission overlaps CPU preparation/wait: do not add those two costs. `vblankHz` is counted independently by the SDK blank observer. All diagnostics stay local.

Local performance messages now include cumulative `shaders` counters: extension/prepass enablement, requested/completed programs, completion-before-use and blocking-path counts, and CPU time spent issuing compile/link requests and querying validation. `prepassMs` includes compilation/link request work and warm discovery scans; these counters overlap and must not be added as disjoint frame costs. They do not measure GPU execution or physical presentation. Cumulative `imageLookups.shortcutHits` counts ordinary texture lookups that bypassed map search; `mapLookups` counts searches, including searches that found an existing image. These exclude render-target views and legacy fallback paths. `constantPacking.reuses` and `packs` count programmable bank reuse versus new owned packets; fixed/pretransformed draws are excluded. `textureMetadataLookups` counts versionHits/versionSearches and copyHits/copySearches in SubmitDraw; searches include successful map finds, and render-target views are excluded. Counters are snapshotted by value in existing present callbacks. Source text remains player-local.

With `?gpuTiming=1`, the renderer independently checks the elapsed-query extension and counter bits on its own context. It samples every sixth frame, holds at most four active/pending queries, and keeps the latest 120 `[frame, milliseconds]` results in local `gpuTiming` performance messages. Queries start after CPU geometry packing, cover buffer uploads, draws and presentation blit, and end before flush. Results are harvested only when available; disjoint results and stale queries are discarded. Stop, command failure and context loss release owned queries. This span may include CPU submission gaps and work across command flushes; it is not pure summed GPU execution or physical frame latency. Unsupported or default-disabled contexts issue no query operations.

Use `?pacingTiming=1` to measure host waits and pipelined presentation locally. The `pacingTiming` field in `globalThis.fuzionPerformance` caps each stream at 120 samples per metrics window. Frame cap, vertical blank and event hold each sample one in four calls in the precise pacing path. Wait rows are `[queuedAt, deadline, workerStart, signalledAt, waitFinishedAt, timerCount, precisionMs]`. Compare `waitFinishedAt` with the deadline to measure release lateness. `precisionMs` is elapsed polling time on the waiting game thread. Present rows are `[frame, previousFlightWaitMs, queuedAt, workerStart, aboutToAck]`. Timestamps are in milliseconds on the shared browser clock. `geometry.geometryPackingMs` measures JS packing before uploads. `geometry.rawStreamDraws` counts original draws and `geometry.rawStreamRows` counts bridge rows in the last frame. `geometry.directVertexBytes` counts logical vertex bytes read directly from Wasm. `geometry.gpuVertexUploadBytes` and `geometry.gpuIndexUploadBytes` count bytes actually sent to WebGL. `geometry.geometryUploadMs` includes the buffer comparison and upload calls.

Resource waits of at least 0.5 ms appear as `pacingTiming.resourceWaits` rows of `[header, type, canonicalData, waitMs, batch, finishedAt, lastHeaderBatch, completedBefore, allocationBytes]`. The duration measures the fence wait after submission. The last-use batch tracks the exact header. An allocation size of zero leaves the extent unknown. The header and backing are local diagnostic values. `rawDrawReuses` counts prepared packets reused since start.

Startup now shows progress beside Start/Stop, locks setup inputs during boot and stops the loading indication on first frame. Per-frame status DOM rewrites were removed. Context loss returns a restart message. Full-window aspect-preserving presentation and reduced-motion handling remain; automated fullscreen previously received a browser denial, so physical fullscreen interaction remains unconfirmed.

## Local shader warmup

WebGL2 warmup is enabled when parallel shader compilation and local storage are available. Successful links teach shader pairs, and validated warm matches refresh their recency. Changes are batched for about a second, and Stop game flushes pending writes. A later start at the same origin links known pairs during loading. The cache is scoped to the verified executable and retains up to 64 recent pairs and 1 MiB in origin-local storage. To disable warmup, add `?shaderWarmup=0` to the launch URL. [Cache API](https://w3c.github.io/ServiceWorker/#cache-interface)

The cache opens alongside Wasm initialization. Exact generated vertex and fragment GLSL share one link job and one ready program across draw variants. Each variant retains its own fallback admission and state keys. Before boot, the renderer reflects completed links, newest recipes first, with an 8 ms soft budget. Those programs can draw without a first-use link or uniform query. The runtime validates all remaining links before use. `warmupPrimed` counts the programs ready at boot, `warmupPendingClaims` counts unfinished preparations carried into play, and `programReuses` counts shared live links. To clear the recipes, run `await caches.delete('fuzion-webgl-shader-recipes-v1')` in the browser console while the game is stopped.

## First-use shader fallback

WebGL2 uses the prepared fallback by default when the required GPU vertex features are available. The browser starts the smooth and flat fixed-function links after verifying the local executable. It starts the programmable link once Wasm exposes the SDK vertex template. All three finish during loading. While a covered specialized link compiles, a ready program draws from the same geometry, texture and constant packets. The SDK supplies checked state keys for supported float vertex attributes and ordinary 2D texture stages. The programmable fallback uses the observed smooth six-register layout with a signed integer register and a BGRA register. It shares SDK input conversion and the position epilogue, with checked instructions in a 2,176-byte uniform buffer. Other layout and texture combinations still use the specialized path and can wait on a cold link. [Khronos parallel compilation specification](https://registry.khronos.org/webgl/extensions/KHR_parallel_shader_compile/)

Pipelined frames with deferred GPU validation draw covered cache misses using the ready fallback. The actual draw queues the specialization. A signalled frame fence allows one step, either a cold link submission or a completion check and uniform reflection. The queue has at most one new cold link in flight and keeps covered draws on the fallback until reflection finishes. `deferredLinks`, `deferredProgramsReady` and `deferredWorkMaxMs` measure that work. Add `?shaderFallback=0` to use the specialized path for every draw or `?shaderWarmup=0` to bypass saved recipes.

When `KHR_parallel_shader_compile` is unavailable, covered draws use the resident programs for the entire session. This avoids first-use compile, link and uniform queries for those draws. Startup pays for the resident links, and the general shaders may cost more GPU time on some workloads. Uncovered draws still link specialized programs when needed. Both `?shaderFallback=0` and `?shaderPrewarm=0` select the specialized path on these contexts.

## Remaining work toward modest-PC 60 FPS

A true lock for all gameplay is **not established**. The measured machine is powerful. The browser rejected CPU throttling on worker targets, so page-only throttling must not be passed off as a low-end Wasm-worker benchmark. Actual integrated-GPU laptop runs, a declared device/browser matrix, longer scenes/full rounds and all minigames remain necessary.

The next changes should stay targeted to measured costs:

1. **Guest scene setup.** Look for repeated inputs and reusable exact arithmetic in Water Gate Scramble's grid-mask pass. The 123.58 ms gap includes 107.56 ms of active guest work. Twisted System still has a 53–56 ms gap with about 37–39 ms of active guest work. Erodeo's measured first scene-entry gap was 38.60 ms, followed by a 43.22 ms gap that includes WebGL submission. Preserve guest timing, draw ordering and checked memory.
2. **Shader first use.** Profile scenes that still show blocking specialized links. Extend fallback admission from actual shader layouts and verify image fidelity and device coverage.
3. **Compressed uploads:** defer the private [S3TC](https://registry.khronos.org/webgl/extensions/WEBGL_compressed_texture_s3tc/) prototype until an actual title texture requiring it is confirmed. The observed routes exercised only RGBA uploads. Any later integration needs native block/alpha/dimension checks, RGBA fallback and explicit qualification of hardware interpolation differences.
4. **Presentation pacing.** Chrome traced all 340 ready Erodeo frames through swap and presentation feedback. Measure repeatable gameplay at a verified 60 Hz or 120 Hz presentation cadence and check replay-transition timing. Keep the original virtual-blank period and callback sequence.
5. **Modest hardware:** measure GPU execution on an actual integrated-GPU laptop. Add internal resolution/quality controls only for confirmed GPU bottlenecks; they cannot remove CPU preparation cost. Preserve logical UI coordinates and readback behavior when introducing physical target scaling.

The requested later target is consistent 120 FPS after stable 60 FPS frame timing. `app::Pace` in `runtime/browser/sdk/full-platform.cpp` reads `app::Get().fps_cap`, while the SDK `VerticalBlank` loop still schedules 16,667 us guest events and callbacks. The timer adjustment keeps both deadlines and the blank event sequence. A 120 FPS implementation needs an 8.33 ms render budget and evidence that input, physics, animation and game timers retain their original behavior; raising a cap or doubling guest blank callbacks alone does not establish this.

MB07 timing, MB14 textures and MB15 shader integration have prototype evidence; their acceptance states and M44 remain unchanged.

Known rendering limits remain: 3D/cube textures and F16/F24 depth formats are unsupported; sampling is base-level only; depth CPU initialization/readback is incomplete; EQUAL-depth bit equivalence is unproved; triangle admission is not a full Xbox drawing API. Erodeo character/corner surfaces and intermittently missing text still need native-reference comparisons. Physical gamepads and audible output were not verified in this batch. Browser settings and native UI replacement parity remain separate work.
