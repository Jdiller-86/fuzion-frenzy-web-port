# Continuous development goal

Deliver the actual original Xbox Fuzion Frenzy executing entirely inside a desktop browser through static recompilation to WebAssembly, then complete the planned fidelity, controls, online and social features. Original game content stays player supplied and local. Do not substitute a streamed/native runtime or approximate replica, and do not call a component fixture or translated-function count playable.

## Operating loop

Use the dedicated source-only OpenCode worktree. At each cycle, read `AGENTS.md`, `docs/DEVELOPMENT_HANDOFF.md`, `docs/PROJECT_STATUS.md`, the active checkpoint and `docs/DECISIONS.md`. Select one **unowned** task that advances original execution toward a controllable original screen. Give it an observable acceptance result, scope and targeted checks. Preserve existing worktree edits and do not duplicate another active task. The current renderer path, not the completed memory-statistics milestone, determines the next task.

Execute a task rather than producing only a plan. The dedicated worktree has no player-supplied game files or ignored research inputs. If the next original-runtime proof requires those inputs, do not claim the proof happened; choose a source-owned prerequisite that can be completed and checked here, or record the exact blocker and move to another independent task. The runner continues one pinned OpenCode session when its ignored `.worktrees/opencode-cycle-session.txt` is present. Without that file, it carries a short previous-cycle report as untrusted context; verify it against files before acting.

Delegate source discovery to local Qwen only after a real OpenCode Scout handoff passes; its current first-turn context error makes it optional. DeepSeek Go implements. Ask Go GLM 5.3 for independent review of CPU, memory, ABI and GPU changes. Call Sol automatically for a route or cross-subsystem decision, after two targeted failed attempts, or when GLM leaves a material correctness question unresolved. Give Sol the concise evidence and decision needed; accept one bounded recommendation per decision, then return implementation to DeepSeek. Do not invoke Sol for routine coding or repeat the same escalation without new evidence.

After each task, run targeted checks, update the lane-owned checkpoint (and `PROJECT_STATUS.md` for the primary lane), record consequential decisions, review the staged source-only paths, and commit the bounded result on that lane's development branch. Record observed runtime behavior and remaining gaps. Continue to the next unowned task only after the prior task has a reviewed result and an identifiable next step. A failed check stops that cycle; the next scheduled cycle investigates or chooses another independent task. On a recognized Go allowance or model-availability failure, the runner retries this task in the same pinned session with the verified free DeepSeek route, then free GLM Flash if needed; other failures wait for the next interval. The model and cooldown are recorded in lane state. The Windows runner publishes checked commits to each GitHub development branch after a successful cycle and records publication failures for retry. Never push or merge to main automatically. Preserve evidence and source-publication guards even when progress is slow.

## Round-the-clock local cycle

Windows Task Scheduler runs `tools/Invoke-OpenCodeCycle.ps1` every five minutes on a daily recurring trigger while this user is signed in and the PC is awake. Task name: `FuzionFrenzy-OpenCode-Cycle`. One invocation runs at most one DeepSeek builder prompt, with project step caps and an exclusive lock against overlapping runs. The task action and launcher both set the dedicated worktree as OpenCode's working directory. The runner uses OpenCode's shared background service, which Desktop also uses, and a local session pin makes subsequent cycles continue the same session under `Fuzion Frenzy Web Port / opencode-source`; old `system32` sessions and the older paused architect goal are unrelated. The runner may fast-forward the worktree to a newer reviewed main commit, and continues on its own branch if main diverges. It resumes worktree edits from a prior cycle without discarding them. Failed or no-progress runs are recorded and retried on later intervals, with Sol escalation after repeated no-progress cycles. State and local-only logs live under ignored `.worktrees/`. Go Extra Usage is off; a quota/auth failure retries later. Sol may be called as a bounded subagent under the escalation rules. Do not manually edit the dedicated worktree while the scheduled agent owns it.

The separate `FuzionFrenzy-OpenCode-Geometry` task runs `tools/Invoke-OpenCodeCycle.ps1 -Lane geometry` hourly with its own `opencode-geometry` worktree, session pin, lock and log. It owns only source-owned NV2A geometry components, matching tests and the geometry checkpoint. The primary lane excludes new geometry component tasks. These two lanes can overlap, but neither may merge the other's branch or modify the other's files. Geometry uses only `opencode/deepseek-v4.1-flash-free`; if that temporary free route is unavailable, it retries later instead of consuming Go or Codex allowance. It does not delegate to paid or other-model agents; unresolved correctness issues are handed to the primary lane. See [the lane ownership table](OPENCODE_WORKFLOW.md#source-control-and-github).

The schedule runs under this user's interactive login. A 90-minute primary limit and shorter geometry limit release hung cycles so later triggers can retry; each lane's exclusive lock prevents overlap within that lane. Uncommitted work in the pinned session is continued with a short completion prompt. The runner compares each branch head and a local worktree fingerprint before and after each cycle: changed unfinished work is `resume`, an unchanged cycle is `no_progress`, and only actual retry/no-progress/interrupted outcomes count toward repeated-failure escalation. The old `system32` sessions have no remaining queued Fuzion prompts and are archived; use the project-bound Desktop tabs for progress. Wake timers may resume tasks from sleep when supported by Windows and hardware, but they cannot run while the PC is off or signed out. Inspect the tasks with `Get-ScheduledTask -TaskName FuzionFrenzy-OpenCode-*`; stop either with `Disable-ScheduledTask -TaskName <task name>`.

Read AGENTS.md, the current handoff, status, decision log and active checkpoint. Define the next unowned milestone with acceptance criteria. Delegate bounded implementation to the DeepSeek Go builder and independent CPU/memory/ABI/GPU review to Go GLM where needed. Use local Qwen only after its OpenCode handoff works. Resolve consequential design questions with evidence, update the project record, and advance to the next milestone when the previous one is verified. Keep each cycle bounded; retry transient failures on a later cycle and choose a different task when an evidence blocker is persistent. Do not duplicate another active task or claim playability without a controllable original screen.

For lower Sol usage, start the same goal with `builder` as primary. It may now summon `architect` automatically under the escalation rules. Starting `architect` as the primary means Sol handles every coordinator turn, including routine ones, so it consumes more of the linked account allowance.
